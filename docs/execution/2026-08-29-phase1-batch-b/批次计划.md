## 2. 设计取舍

- **PG 单后端**：P1.7 验收只需「可保存/恢复」；Redis 后端到 P3.1（WAITING_USER 可恢复中断需要 TTL）再引入，避免双后端同时无调用方的空转维护。
- **领域级 checkpoint 而非 LangGraph 原生 checkpointer**：当前循环无 `interrupt()`，`run_agent` 的 astream 累积已覆盖保存/恢复语义；LangGraph 原生 saver（含 pending 通道恢复）随 P3.1 interrupt 一起做。
- **测试门控**：集成测试沿用仓库惯例 `KNOWLEDGE_TEST_DATABASE_URL` 门控（缺省 skip）；本批验收额外用一次性 Docker PG 真实跑通。

## 3. 验收标准

- 序列化往返：五态槽位、观测（含 data）、pending 三件套、steps/stop_reason/answer 无损（除文档声明的 data 降级）；未知版本拒绝。
- 幂等：同 command_event_id 重复 start_run 返回既有 run_id（created=False）；不同 event 各自成 run；同 (run_id, seq) 重复 record_step 不产生双行。
- checkpoint：save → load 往返一致；未知 run 返回 None。
- `checkpoint_sink`：脚本化决策 run 中逐节点回调，末次状态与最终结果一致。
- 全量基线 **1794 passed 不降**（DB 门控测试在本环境 skip 属预期，pass 数为门禁口径）。
