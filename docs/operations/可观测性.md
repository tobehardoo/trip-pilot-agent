## 定位

本项目的可观测性首先服务于本地调试和自动化验证。健康检查与 Prometheus 随 Compose 提供；外部告警平台、长期日志存储和生产值班不属于当前完成条件。

## 健康检查

| 服务 | 端点或方式 | 用途 |
| --- | --- | --- |
| Java API | `GET /api/health` | 检查应用及依赖状态 |
| Agent API | `GET /health` | 检查 Python API 存活 |
| Web | `GET /` | 检查本地 Web 入口 |
| Prometheus | `GET /-/healthy` | 检查可选指标服务 |
| Compose | `docker compose ... ps` | 查看容器健康与一次性任务结果 |

`knowledge-init` 是一次性任务，成功退出表示迁移和知识初始化完成。

## Prometheus（可选）

本地默认地址为 `http://127.0.0.1:9090`，端口由 `PROMETHEUS_PORT` 调整。可用于观察：

- 规划任务成功、失败和取消。
- 规划阶段耗时和 Provider 结果。
- HTTP 请求、JVM 与队列相关指标。
- RabbitMQ ready/unacked 数量和任务终态分布。

Prometheus 不影响 Demo 主旅程；资源不足时可只使用健康检查和容器日志排查。

## 日志现状与规则

Python、容器和基础设施已有可用日志，但 Java 应用层结构化日志仍明显不足，是路线图中的 P2 工作。当前文档不把尚未落地的 `traceId`/MDC 方案描述为已完成能力。

新增日志时应优先包含非敏感关联标识：

- `traceId`
- `tripId`
- `taskId`
- `messageId`
- `provider`

Provider 回退使用稳定事件名 `planning_provider_fallback`，记录操作、原因、重试次数和关联 ID。

禁止记录：

- JWT、Cookie、Authorization 和内部 Token。
- AMap、QWeather 或其他服务 Key。
- 完整 Provider 请求/响应。
- 用户敏感输入和完整攻略正文。
- 可能包含以上内容的未脱敏异常上下文。

## 诊断与失败消息

受 `INTERNAL_DIAGNOSTICS_TOKEN` 保护的内部诊断入口用于：

- 查看失败任务的脱敏上下文。
- 对允许重试的失败任务执行幂等重试。

RabbitMQ 死信队列保存无法正常消费的消息。Transactional Outbox 在达到最大尝试次数后会标记 dead，避免毒消息无限占用发布槽位。排查时应区分“业务规划失败”“消息消费失败”和“Outbox 发布失败”。

## 本地观察清单

| 场景 | 建议观察 |
| --- | --- |
| 规划卡住 | Worker 日志、任务状态、RabbitMQ ready/unacked、SSE 最后阶段 |
| Provider 失败 | mode、operation、安全错误分类、retry count、是否显式 fallback |
| 完成未展示 | completion 消息、Java 消费、版本记录、SSE 终态 |
| 重复版本 | messageId、幂等记录、任务与版本数量 |
| 启动失败 | Compose health、`knowledge-init` 退出码、数据库迁移日志 |

## 可选告警示例

如果开发者自己接入本地或个人告警工具，可关注服务离线、队列持续增长、规划失败率和 Provider 连续失败。这些是调试建议，不是项目合并或完工门槛。
