## 1. 交付声明规则

只有同时存在以下证据，功能才可以标记为已交付（`DONE`）：

| 证据类型 | 要求 |
|---------|------|
| 代码实现 | 业务逻辑、模型、持久化和接口已合并至主分支 |
| 数据库迁移 | Flyway 迁移已应用，升级路径已验证 |
| 服务契约 | JSON Schema 已更新，Java/Python/TypeScript 三方同步 |
| 前端交互 | 页面可操作，状态可恢复，错误有提示 |
| 单元测试 | 覆盖核心逻辑和边界条件 |
| 集成测试 | 跨层或跨服务验证通过 |
| E2E | Playwright 浏览器验收通过 |
| 发布环境验收 | Docker Compose 全栈健康检查通过 |
| 文档同步 | 相关维护文档已更新 |

**不被接受的证据**：

- 接口存在但页面未接入，不算交付
- 页面使用 Mock 数据，不算真实交付
- 单测通过但无跨服务验证，不算完整交付
- Demo Provider 通过不能替代真实 Provider 验收
- 仅计划文档描述，不算完成

## 5. 核心 E2E 场景

### E2E 1：行前准备

```text
创建广州三日旅行
  → 导入官方攻略和天气事实
  → 生成行程
  → 自动生成行前准备清单（预约、门票、天气等）
  → 用户标记几个事项为已完成
  → 页面刷新后准备状态保持
  → 验证：强制事项标记为 required，社区建议不标记为 required
```

### E2E 2：旅行当天延迟与重规划

```text
进入今日行程页面（手机视口）
  → 完成第一个活动（标记 COMPLETED）
  → 第二个活动因排队延迟 1 小时
  → 用户请求重规划当天剩余行程
  → 已完成活动保持不变
  → 剩余活动重新安排
  → 创建新 IN_TRIP_REPLAN 版本
  → 版本差异显示变化原因
```

### E2E 3：天气变化触发调整

```text
当日预报从晴变为降雨
  → 打开今日模式，风险复核检测到天气变化
  → 显示风险提示："今日下午有雨，室外活动可能受影响"
  → 用户确认调整
  → 室外活动被替换或降权
  → 生成新版本，差异说明引用天气事实
```

### E2E 4：消费记录与总结

```text
记录交通费用 ¥32、餐饮 ¥160、门票 ¥60
  → 查看今日预计 ¥200 vs 实际 ¥252
  → 完成全部活动
  → 标记旅行结束
  → 生成总结：完成率 100%，实际花费超预算 26%
  → 总结中列出用户反馈
```

## 7. 未交付和部分交付规则

- 功能代码存在但未接入端到端验证 → `IMPLEMENTED`，不可标记 `DONE`
- 页面存在但依赖 Mock 数据 → `IMPLEMENTED`，不可标记 `DONE`
- 因外部服务阻塞（如高德 API 配额、域名白名单）→ `BLOCKED_EXTERNAL`
- 因内部依赖未完成（如 Phase 1 未完成导致 Phase 3 无法开始）→ `BLOCKED_INTERNAL`
- 发现的问题不能通过删除交付条目来隐藏
- 降级或简化实现必须在已知限制中如实记录
