## 2. 两个「移除测试」

**「如果移除 LLM，这个系统是否只是一个传统固定流程系统？」**
当前：是——唯一可运行的决策策略是固定的。但需精确归因：确定性退化本身是设计（ADR-007 Demo 可跑、可复现），不是缺陷；真正的问题是**「有 LLM 的动态决策路径也没有」**（问题 F4：决策器未接线）。P1.9 完成后：无 Key = 固定引出策略（可复现、可演示），有 Key = 基于状态与观测的动态决策。确定性内核（OR-Tools 调度、Hard Validation）保持确定性是有意的可靠性设计（ADR-015 §2），不属于本判据的失败对象——判据对象是 Agent 决策层是否真实存在且可运行。

**「如果移除大量无意义的 Agent 概念包装，系统核心能力是否依然只是一个 LLM 调用链？」**
不是。槽位出处模型（INFERRED/REJECTED 禁作硬约束）、fail-closed 工具语义、validate 一票否决、有界循环都是可测试的真实机制，不是包装。且项目已经克制：无 Multi-Agent / Supervisor / 无端 Memory（ADR-010 单 Agent 决策）。前瞻检查：P2.5 intent 节点、P2.6 critic 节点引入前必须回答三问（解决什么实际问题 / 不引入有何明确缺陷 / 是否提升决策、执行或可靠性）——critic 走建议通道（不回写硬约束）可论证；intent 节点需先给出多轮混合意图出现频率的证据再立项。
