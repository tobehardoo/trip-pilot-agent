# 事件契约

- 文档状态：生效中
- 最后更新：2026-08-29
- 范围：Java（travel-server）⇄ Python（agent-service）经 RabbitMQ 交换的命令与事件
- 权威原则：JSON Schema 是契约权威；变更走 `schema_version` 演进，历史事件只读兼容（ADR-014）

## 1. 交换与路由

| 组件 | 名称 |
|---|---|
| 命令交换 | `trip.command.exchange` |
| 事件交换 | `trip.event.exchange` |
| 死信交换 | `trip.dead-letter.exchange` |
| 命令队列 | `planning.create.queue` / `planning.cancel.queue` |
| 事件路由键 | `planning.completed` / `planning.review-required` / `planning.progress` 等 |

## 2. 命令（Java → Python）

| 命令 | schema_version | 说明 |
|---|---|---|
| `PLANNING_CREATE_REQUESTED` | v4 | 首次规划；含 TripSnapshot、约束、攻略证据、规划上下文快照 |
| `PLANNING_REPLAN_REQUESTED` | — | 局部重规划；含 impacted_dates |
| `PLANNING_CANDIDATE_VALIDATION_REQUESTED` | — | 编辑/回滚候选的验证（不可变编辑链） |
| `PLANNING_CANCEL_REQUESTED` | — | 协作式取消 |

命令公共字段：`event_id`（幂等键）、`trace_id`、`task_id`、`trip_id`、`occurred_at`。

### 2.1 规划中：Agent 命令

| 命令 | 说明 |
|---|---|
| `AGENT_START` | 对话式命令进入 Agent 编排路径（规划中，Agent化路线图 Phase 2） |
| `AGENT_RESUME` | 用户回答回灌，恢复 WAITING_USER 中断点（规划中，Phase 3） |

## 3. 事件（Python → Java）

| 事件 | schema_version | 说明 |
|---|---|---|
| `PLANNING_PROGRESS` | v2 | 进度阶段 + 统计；阶段枚举见 `worker/contracts.py` `PlanningProgressStage` |
| `PLANNING_COMPLETED` | v11 | 成功终态；payload 含 itinerary、knowledge、evaluation、feasibility_report、fact_impacts |
| `PLANNING_REVIEW_REQUIRED` | v2 | `WAITING_USER` 终态；保留候选、证据与失败原因，不修改正式版本 |
| `PLANNING_FAILED` | v2 | 终态失败；error_code / conflicts / relaxation_suggestions |
| `PLANNING_CANCELLED` | — | 协作式取消确认 |

事件公共字段：`event_id`（由命令 event_id 确定性派生，重试可复现）、`run_id`。

### 3.1 规划中：Agent 事件

| 事件 | 说明 |
|---|---|
| `AGENT_STEP` | 结构化轨迹事件：工具名 + 摘要 + 状态 + 耗时（克制版推 SSE，原始轨迹走查询 API） |
| `AGENT_ASK_USER` | 澄清问题（含 options 候选），升级替代 WAITING_USER 终态（Phase 1） |
| `AGENT_COMPLETED` | 有界循环验证通过并自动发射候选行程（含 slots 投影，P2.8b） |
| `AGENT_RUN_FINISHED` | v1：无问题、无行程的终态闭环（STOPPED/FAILED/EXPIRED/ANSWERED + reasonCode + 用户安全文案）。覆盖 CEILING_REACHED、等待过期、resume 被拒（先发事件后进死信）与纯文本回答——没有它前端会永远等待（Agent UX 2.0 P0） |

## 4. 幂等与可复现（ADR-012）

- 完成/失败事件 id 由命令 `event_id` 经 uuid5 确定性派生，命令重试总是产生同一事件。
- Java 侧对事件去重；Python 侧对命令幂等（任务级幂等键）。
- 规划消费冻结事实快照：重试不因后续事实刷新而改变任务输入。

## 5. 契约同步纪律

- 任何契约变更必须同步：JSON Schema（`contracts/`）、Java parser、Python `worker/contracts.py`、TypeScript 类型、示例消息。
- 不修改已发布的 schema_version；新增字段走新版本，Java/Web 对缺失字段保持读取兼容。
