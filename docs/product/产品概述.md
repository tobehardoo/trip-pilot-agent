## 项目定位

TripPilot 是面向国内单城市自由行的约束驱动旅行规划系统。它以本地 Docker Compose 为主要运行方式，默认使用不依赖外部凭据的 `DEMO_ONLY` 模式，真实 Provider（高德、QWeather）为可选增强。

**当前主线（v1.1）**：在约束驱动定位上叠加 Agent 编排层——LLM 负责意图理解、约束收集与澄清，调度求解与可行性校验仍由确定性系统守门。产品定义（完整、真实、可执行）不变，Agent 化只是实现方式的演进，见 [Agent化路线图](Agent化路线图.md)。

## 产品定义：完整、真实、可执行

TripPilot 的核心交付物是"完整、真实、可执行的旅行计划"。

- **完整（Complete）**：多日行程应覆盖到达、离开、住宿语义、游览、餐饮、活动间交通和跨日衔接。
- **真实（Authentic）**：POI、路线、营业时间等外部事实应保留来源和新鲜度；推导值应可解释；Demo 或估计结果必须明确标识。
- **可执行（Executable）**：硬规则决定行程是否可作为可执行计划，体验评分只评价已经可行的方案。硬校验失败应进入修复、重规划或明确失败，不能用高分掩盖不可行。

## 主要用户旅程

1. 用户提出出行意图（表单或自然语言对话）。
2. 系统收集并确认约束（目的地、日期、预算、必去、固定安排等）。
3. Agent 编排 + 确定性规划生成候选行程，异步推进并经 SSE 推送进度。
4. 可行性校验通过后成为正式版本；用户可编辑、重规划、回滚，均形成新版本。
5. 行程可分享、导出（PDF/ICS），并附带证据与解释。

## 边界

- 单城市自由行；跨城市联程、公网部署、多用户协作不属于当前范围。
- 网页攻略导入仅支持可公开访问的静态 HTTPS 页面；动态渲染或登录墙页面改用粘贴正文或截图。
- 请求模型（TAXI/AUTO）与持久化模型（WALKING/TRANSIT/DRIVING）严格区分。
