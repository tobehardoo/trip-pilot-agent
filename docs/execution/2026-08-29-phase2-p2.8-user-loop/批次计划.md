## 1. 8a 设计

| 项 | 设计 |
| --- | --- |
| 端点 | `POST /api/trips/{tripId}/agent-dialogue/runs`（消息 → AGENT_START）；`POST .../runs/{runId}/answers`（回答 → AGENT_RESUME）；均 202 + `{eventId, status: "QUEUED"}` |
| 发布 | `AgentDialogCommandService` 构造完整命令信封 JSON（v1 契约，含可选 userId=P3.2 profile 身份）→ `OutboxEventRecord`（PENDING，routing key `agent.start`/`agent.resume`）→ 既有 outbox job 发布——**事务性 outbox，零新发布机制** |
| 幂等 | 可选 `Idempotency-Key` 头作为命令 eventId；主键冲突视为同键重放，返回同一 QUEUED 响应 |
| 守卫 | 所有权经 `TripService.get`；消息/回答长度与空白校验（与契约一致） |
| 拒绝反馈 | resume 的生命周期拒绝（P3.1 原因码）走死信；用户可见的过期/进行中提示随 8b 轮询/事件渲染 |

## 2. 8a 验收标准

- 两端点写出的 outbox 记录：路由键、eventType、信封字段（含 userId/runId）与 Python 侧 pydantic 契约一致（JSON 往返断言）。
- 所有权 404、非法消息 400、幂等重放同响应。
- mvn 相关测试全绿；Python 契约测试不受影响。
