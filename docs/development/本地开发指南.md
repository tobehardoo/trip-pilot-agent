## 前置条件

- Docker Desktop 或 Docker Engine
- Docker Compose v2
- 建议至少 8 GB 可用内存
- Java 21（如需在宿主机运行 Java 测试）
- Python 3.12+（如需在宿主机运行 Python 测试）
- Node.js 和 pnpm（如需在宿主机运行 Web 测试）

## 快速启动

### 1. 创建本地配置

```powershell
Copy-Item .env.example .env
```

Linux/macOS：

```bash
cp .env.example .env
```

在 `.env` 中至少替换以下本地密钥（不要将真实密钥提交到仓库）：

```dotenv
POSTGRES_PASSWORD=your-local-postgres-password
REDIS_PASSWORD=your-local-redis-password
RABBITMQ_PASSWORD=your-local-rabbitmq-password
JWT_SECRET=your-random-secret-at-least-32-bytes
AGENT_INTERNAL_TOKEN=your-distinct-random-internal-token
INTERNAL_DIAGNOSTICS_TOKEN=your-distinct-random-diagnostics-token

# 本地 Demo 模式（无外部凭据）
PROVIDER_MODE=DEMO_ONLY
REFRESH_COOKIE_SECURE=false
```

### 2. 启动完整系统

```powershell
docker compose -f compose.prod.yaml --env-file .env up -d --build --wait --wait-timeout 180
docker compose -f compose.prod.yaml --env-file .env ps
```

默认访问地址：

- Web：`http://127.0.0.1:8080`
- Prometheus：`http://127.0.0.1:9090`

端口可通过 `.env` 中的 `WEB_PORT` 和 `PROMETHEUS_PORT` 调整。

首次启动时，`knowledge-init` 容器会迁移数据库并导入随仓库提供的广州知识。

### 3. 查看日志和停止

```powershell
docker compose -f compose.prod.yaml --env-file .env logs -f
docker compose -f compose.prod.yaml --env-file .env down
```

数据默认保留在 Docker Volume 中。仅在明确要清除本地演示数据时执行 `down -v`。

## 使用真实 Provider

本地 Demo 不依赖外部地图、天气凭据。要启用真实高德规划和 QWeather 城市天气：

```dotenv
PROVIDER_MODE=REAL_ONLY
AMAP_WEB_SERVICE_KEY=your-server-side-amap-key
QWEATHER_API_KEY=your-server-side-qweather-key
QWEATHER_API_HOST=your-dedicated-qweather-api-host
VITE_AMAP_WEB_JS_KEY=your-browser-amap-key
VITE_AMAP_SECURITY_CODE=your-browser-security-code
```

**注意事项：**

- `PROVIDER_MODE` 是权威配置；`DEMO_MODE` 仅用于旧部署兼容。
- 服务端 Web Service Key 与浏览器 Web JS Key 必须分开使用。
- QWeather Host 必须使用控制台为账号分配的 HTTPS Host，不能把开发默认 Host 当作生产验收结果。
- 生产环境还必须配置 HTTPS、`REFRESH_COOKIE_SECURE=true`。

## 各服务独立开发

### Java（travel-server）

```powershell
# 编译和测试
mvn --batch-mode -pl apps/travel-server verify

# 仅编译
mvn --batch-mode -pl apps/travel-server compile

# 运行特定测试
mvn -pl apps/travel-server -Dtest=ItineraryEditFlowIntegrationTest test
```

Java 测试使用 Testcontainers 自动启动 PostgreSQL。

### Python（agent-service）

```powershell
cd apps/agent-service

# 安装依赖
uv sync --extra dev

# 运行测试（Demo 模式，不消耗配额）
uv run pytest

# 运行真实 Provider 测试（需要真实 Key）
$env:RUN_REAL_PROVIDER_TESTS="true"
uv run pytest

# 静态检查
uv run ruff check .

# PlanEvaluation 基准测试
uv run python benchmarks/run_plan_evaluation.py
```

### Web（Vue 3）

```powershell
cd apps/web

# 安装依赖
corepack enable
pnpm install --frozen-lockfile

# 开发服务器
pnpm dev

# 测试
pnpm test:coverage

# 类型检查
pnpm typecheck

# 生产构建
pnpm build

# 浏览器端到端测试
pnpm test:e2e
```

## Provider 模式配置矩阵

| 场景 | PROVIDER_MODE | 需要 Key | 预期行为 |
| --- | --- | --- | --- |
| 本地开发 | `DEMO_ONLY` | 不需要 | Demo 通过，不发起外部调用 |
| Staging/生产 | `REAL_ONLY` | 需要 | 真实 Provider，失败即失败 |
| 内部演示 | `REAL_WITH_EXPLICIT_FALLBACK` | 需要 | 真实优先，特定失败可降级 Demo |
| 非法模式 | 其他值 | — | 启动失败 |
| 冲突配置 | `PROVIDER_MODE` 和 `DEMO_MODE` 冲突 | — | 启动失败 |

## 常见问题

### Docker Compose 启动失败

1. 检查 Docker Desktop 是否运行。
2. 检查端口 `8080`、`9090` 是否被占用。
3. 检查 `.env` 中的密钥是否已替换为占位值。
4. 检查可用内存是否达到 8 GB。

### Java 测试在 Windows 上的路径问题

Windows 本地 Maven 需显式指定 ASCII JaCoCo 数据路径。如果遇到非 ASCII 工作区路径导致的 JaCoCo 错误，在 Maven 命令中指定 ASCII 临时目录。

### Python 测试权限错误

Windows 上的 pytest 临时目录可能存在历史权限污染。使用明确隔离的临时目录：

```powershell
uv run pytest --basetemp=.pytest-temp-clean
```

### 端口冲突

修改 `.env` 中的 `WEB_PORT` 和 `PROMETHEUS_PORT` 来避免端口冲突。
