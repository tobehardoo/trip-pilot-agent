## Phase 1（本轮实施）— P1 产品可信度

### 1a · 成本溯源全链路透出（B1，R1/P1）

目标：用户看到的每一项费用都携带「估算 or 真实」的来源，绝不因链路丢失而让估算显得权威。

链路：

```
Python 打标(RULE_ESTIMATE/CITY_ESTIMATE/…) → PlanningCompletedEvent
→ Java 落库(itinerary_activity.cost_source) → 读模型
→ API DTO 透出 activity.costSource/estimated → 前端徽标
```

交付：

- Python：确认估算打标进入完成事件活动字段（`contracts.py`、`cost_model.py`）。

- Java：`PlanningCompletedEventParser` 解析 `costSource` → 落库列 → 活动读模型 `costSource` → API（`/api/trips/:id/itinerary`）透出。

- 前端：`plan-activity-*` 每活动贴「估算」徽标；`plan-overview-stats` 预算卡标注「含估算」；分享页同步；不伪造、RULE\_ESTIMATE/CITY\_ESTIMATE 显式标「估算」。

### 1b · 事实核验三态披露（B2，R2/P1）

目标：营业时间/关键事实不再是「UNKNOWN 直接放行且用户不知情」，而是显式告知核验状态。

```
VERIFIED   → 已核验（绿）
UNVERIFIED → 暂未核验，请出发前确认（黄）
UNKNOWN    → 未获取，不伪造（灰/中性，但显式）
```

交付：

- 复用现有「测试专用」的 `fact-status-presentation.ts` / `feasibility.ts`，接入产品（攻略折叠区、天气条），消灭「写了没接线」。

- 规则仍保持「UNKNOWN 不伪造」不变。

## Phase 3（方向 A 收敛）— 完成 5 件事

1. **明确 Agent 边界**

   - Agent 不负责权威行程求解。

   - Agent 负责：Intent / Conversation / Constraint Collection / Clarification / Modification / Explanation / HITL。

2. **合并双对话体系**

   - 只保留 **一个权威的 Conversation State / Constraint State**。

   - 消除 `Wizard State` + `AgentState` + `Constraint State` 三处各维护一份的冗余。

   - 目标单向流：

     ```
     User → One Conversational Flow → One Constraint Source of Truth → Planning Request
     ```

   - 路径：以 `agent/`（LangGraph + AgentState）为唯一会话入口，`dialog/service.py` 收敛为同一约束状态机的薄适配层。

   - 约束：先定最终架构、再删旧链；**不**贸然并发重构导致系统不稳。

3. **清理 Agent 空转 Tools**

   - 判定：某个 `search_place / get_route / opening_hours` 是否影响用户约束？是否影响权威规划？

   - 两个答案都是 No → 默认删除（或降级为只读说明），不让观察结果只给 LLM 看而空转。

4. **消除 Preview Plan 与 Authority Plan 双链**

   - 审计点：Agent/预览链生成的行程草案与权威 Pipeline 存在两套产出。

   - 收敛：规划唯一的权威出处 = 确定性 Pipeline；清理预览链冗余，避免双份行程状态。

5. **文案与定位收敛**

   - README / 职位描述改为 `Constraint-Driven Travel Planning Engine with a Bounded Conversational Agent`。

   - 健康指标与文档不再宣传「自主规划 Agent」，如实描述默认 `AskingDecider`（确定性）运行形态。
