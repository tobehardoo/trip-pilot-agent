## 3. 实现期发现并修正的问题

- **回合预算累计缺陷**：`steps` / `observations` 跨 resume 累计，多轮对话在第三回合必然撞 MAX_STEPS=8（E2E 先行暴露）——改为回合独立预算：resume 清零 steps、冻结观测基线；工具调用上限按"本回合新增观测数"计。
- **exclude_none 破坏约束再校验**：快照 wire dump 丢掉 `budgetAmount: null` 导致 TripConstraints 重校验失败——命令为进程内对象，直接传模型实例并注释说明。
- 测试侧：TripConstraints 必填枚举（traveler_type/pace）无对话槽位对应，demo builder 以中性默认填充（文档化）；约束断言路径为 `payload.trip.constraints`。

## 4. 遗留与说明

- 默认守门窄于管线 Hard Validation 11/11 规则集（差距文档化）；真实 provider 的 builder 与规则级 parity 随真实 provider 接线批次落地，Java 命令路径仍以管线内守门为权威。
