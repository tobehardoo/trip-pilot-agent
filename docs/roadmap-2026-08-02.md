## 3. 发布层级定义

- **可提交**：职责明确；产品文件均受 Git 管理；不含本地工具目录、测试产物或密钥；触及范围测试通过；无新增 lint；`git diff --check` 通过。
- **可集成**：切片已形成提交且基于明确基线；冲突路径、契约和合并顺序确定；切片门禁通过；合并过程可重复。
- **发布候选**：组合后的单一 SHA 通过 Python、Java、Web、Flyway、JaCoCo、构建、benchmark、Compose 和组合 E2E；配置与文档一致；可部署 staging。
- **可生产发布**：发布候选在真实 HTTPS、域名、Key、Host 和白名单环境通过第三方服务、负向路径、监控告警、备份恢复、回滚和 soak 验收。

工作量口径：S 不超过 1 个开发日；M 为 2–4 个开发日；L 为 5–10 个开发日；XL 超过 10 个开发日。

## 5. 串行与并行关系

主链必须串行：`阶段 0 → 阶段 1 → 阶段 2 → 阶段 3 → 阶段 4 → 阶段 5`，之后进入阶段 6/7。

可以并行：

- 域名、证书、AMap/QWeather Key 和白名单申请可从阶段 0 与阶段 1–3 并行。
- 阶段 1 内 Python、Java、前端、CI/Compose 可并行收口。
- 阶段 3 内 Python、Java、Web、Compose 门禁可并行运行，但放行必须等待全部完成。
- 阶段 4 内 HTTPS、服务端 Provider、浏览器地图、备份和告警可并行验收。

必须串行：

- 保护天气现场先于任何 merge/cherry-pick。
- Ruff 和 `import_city()` 测试先于天气切片进入组合分支。
- `TripDetail.vue` 人工整合和 `TripWorkspace` evaluation 绑定先于组合全量验证。
- 阶段 3 全绿后才能把同一 SHA 部署 staging。
- staging 真实 Provider 与运行验收通过后才能生产上线。

## 7. 最小可发布版本边界

必须包含：现有核心规划/SSE/版本/编辑/失败；三种 Provider 模式；PlanEvaluation 与当前 planning-generated version 正确绑定；legacy/失败/编辑版本不展示错误评分；城市情报、天气时间轴和地图日期联动；天气不可用显式呈现；完整 CI/Compose/监控/回滚；若为公网生产，还必须有真实 AMap/QWeather、HTTPS、白名单和 Secure Cookie 验收。

### 13.16 交通方式选择修复（P0，2026-08-07）

- **根因**：前端 `TransitLegControl.modeHasConflict` 把"估算时长 > 当前行程活动间空档"当作禁用条件，后端 `evaluateTransitLegEdit` 同样以 `ITINERARY_TRANSIT_CONFLICT` 硬阻塞较慢方式——空档不足被误判为"该方式不存在"。
- **锁定来源**：worker 的 TransitLeg 只有 `WALKING|DRIVING` 且无 `locked` 字段；`leg.locked` 只由用户显式 `UPDATE_TRANSIT_LEG transitLocked` 产生，未发现规划器自动锁定 bug。
- **修复语义**（提交 `5d5b955`）：
  - `AVAILABLE`：真实可用且当前空档足够，正常可选；
  - `REQUIRES_REPLAN`：真实可用但空档不足，**仍然可选**，显示"需要调整行程"提示，保存后需调整后续活动时间或重规划该天；
  - `UNAVAILABLE`：真正不可用（Provider 无路线/业务规则/数据缺失）才禁用；
  - `USER_LOCKED`：只有用户显式勾选"锁定此段通勤方式"才禁用其他方式。
- 移除 `queueRecommendedLongWalks` 的自动 `UPDATE_TRANSIT_LEG` 副作用：长步行只展示"推荐公交"标签，不再在用户未操作时悄悄修改行程。
- 后端区分硬约束：目标活动 `time_fixed`（固定预约）→ 预览 `blocked` 清晰原因；普通空档不足 → `allowed` + warning。
- 验收：Web 单测 156 全过（新增 T1–T5）；Java 交通集成 27 tests 全过（`allowsSlowerTransitModeWithAReplanWarning` + `rejectsSlowerTransitModeAgainstAFixedSchedule`）；真实浏览器验收——9 个 transit leg 全部 4 种方式可点，其中 6 个 leg 自然存在紧空档且带"需要调整行程"徽标但仍可点击，手动锁定/解锁行为正确（证据见 `evidence/transit-acceptance/` 与 `evidence/transit-case-c/`，git-ignored）。
