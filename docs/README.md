## 归档文档

[历史归档](archive/README.md) 保存旧文档原文，用于追溯上下文，不再作为当前事实来源。归档包括：

- V1.3 系统状态、发布验收和需求基线。
- V2.0 方针草案、执行清单、发布证据原文和审查报告。
- 原始架构、领域、数据库、规划、部署、API 和完整 ADR 详稿。
- 架构重构执行记录。

## 维护规则

- 当前能力只写入顶层维护文档；归档文档不再更新当前状态。
- 新功能改变用户范围时，更新 [产品与范围](product.md) 和 [发布状态](release.md)。
- 新功能改变服务边界、数据模型、规划流程或可靠性时，更新 [系统架构](architecture.md)。
- 新增或修改 HTTP、消息、SSE、错误码或幂等语义时，更新 [接口与契约](api.md)。
- 部署变量、启动方式、测试门禁、备份恢复或发布条件变化时，更新 [部署与运维](deployment.md)。
- 只有长期有效且会约束后续实现的取舍才进入 [技术决策](decision-record.md)。
- 临时审查、一次性验收和阶段计划先写入归档或发布状态，不新增顶层散文档。

## 快速定位

- 想运行项目：看 [部署与运维](deployment.md)。
- 想了解现在能做什么：看 [产品与范围](product.md)。
- 想改后端、Worker 或 Web 的职责边界：看 [系统架构](architecture.md)。
- 想接入消息或前端事件流：看 [接口与契约](api.md)。
- 想判断是否可发布：看 [发布状态](release.md)。
