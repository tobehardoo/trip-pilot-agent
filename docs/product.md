# 产品与范围

TripPilot 的目标是让自由行规划从“地点清单”变成“可验证、可解释、可恢复的行程版本”。系统先收集用户约束和城市事实，再用确定性规则、Provider 数据和 OR-Tools 求解生成多日行程。

## 当前基线

V2.0 已在本地 Demo/Compose 环境形成交付证据，日期为 2026-07-27。它证明核心闭环可运行：规划、进度、行程编辑、版本、分享、导出、诊断和全栈 Compose 验收。生产环境发布仍需要部署者完成真实域名、HTTPS、Provider Key 和高德 Web JS 底图验收。

## 用户旅程

```text
注册或登录
  -> 创建旅行并填写日期、预算、兴趣、住宿、必去/避开和固定安排
  -> 导入攻略或刷新城市情报
  -> 创建规划任务并查看真实阶段进度
  -> 查看带时间、交通、费用、地图概览和事实依据的行程
  -> 编辑活动或交通，生成新的不可变版本
  -> 比较或回滚版本
  -> 分享只读链接，或导出 PDF / ICS
```

## 已交付能力

- 账号、旅行、约束、归档/恢复、分页筛选和用户数据隔离。
- 异步规划任务，Worker 产生真实阶段事件，Java 幂等持久化并通过 SSE 支持 `Last-Event-ID` 恢复。
- 高德和 Demo Provider 双模式；Demo 模式可复现，真实模式失败必须明确降级。
- 可信城市情报、用户攻略导入、事实新鲜度、证据快照和规划影响展示。
- OR-Tools 时间窗、交通、预算、必去地点、固定安排和不可行解释。
- 行程版本不可变；编辑、局部重规划、差异和回滚都产生可追溯版本。
- 通勤段编辑写回后端，保存方式、距离、时长、费用、Provider 元数据、计算时间和过期状态。
- 匿名只读分享固定到某个行程版本，Token 只保存哈希并支持撤销、过期和限流。
- PDF 与 ICS 导出，PDF 使用可渲染中文字体并经过独立渲染验证。
- 受保护内部诊断入口、Prometheus 指标和生产 Compose 健康检查。

## Demo 与真实 Provider

Demo 模式是正式支持的运行模式，用于本地体验、自动化测试和无 Key 环境。它必须清楚标记估算、缓存或降级结果。

真实 Provider 模式用于生产或接近生产的验收。服务端 Web Service Key、浏览器 Web JS Key、安全密钥和域名白名单必须分开配置；真实底图成功只能在最终浏览器域名中验收。

## 非目标

V2.0 不做机票、火车票、酒店库存、支付、真实预订、多城市联程、多人实时协作、完整 PWA、国际化、Kubernetes 迁移或大型爬虫平台。
