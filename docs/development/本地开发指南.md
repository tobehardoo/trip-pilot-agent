## 开始之前

第一次运行完整系统时，先按[本地运行指南](../operations/本地运行指南.md)创建 `.env` 并启动 Compose。本文档只说明源码开发、按服务测试和调试方式。

宿主机开发工具：

- Java 21 与 Maven
- Python 3.12+ 与 uv
- Node.js、Corepack 与 pnpm
- Docker（Java 集成测试使用 Testcontainers，整栈验证使用 Compose）

## 推荐开发循环

1. 用 `DEMO_ONLY` 复现问题，避免真实 Provider 的网络和配额影响。
2. 在目标服务运行最小相关测试。
3. 完成修改后运行该服务的完整门禁。
4. 涉及消息 Schema、数据库迁移或用户主旅程时，再运行跨层测试和 Compose smoke。
5. 真实 Provider 只作为显式可选验证，不能替代确定性测试。

## Java：travel-server

```powershell
# 完整验证：单元、集成、Flyway 与 JaCoCo
mvn --batch-mode -pl apps/travel-server clean verify

# 仅编译
mvn --batch-mode -pl apps/travel-server compile

# 指定测试
mvn -pl apps/travel-server -Dtest=ItineraryEditFlowIntegrationTest test
```

Java 集成测试通过 Testcontainers 启动 PostgreSQL。

## Python：agent-service

```powershell
cd apps/agent-service
uv sync --extra dev

# 默认测试不消耗真实 Provider 配额
uv run pytest

# 静态检查
uv run ruff check .

# 确定性评估基准
uv run python benchmarks/run_plan_evaluation.py
```

显式运行真实 Provider 测试：

```powershell
$env:RUN_REAL_PROVIDER_TESTS="true"
uv run pytest
```

真实测试需要本机环境中的合法 Key，并可能消耗配额；普通开发和 CI 不应依赖它。

## Web：Vue 3

```powershell
cd apps/web
corepack enable
pnpm install --frozen-lockfile

pnpm dev
pnpm test:coverage
pnpm typecheck
pnpm build
pnpm test:e2e
```

`pnpm build` 是前端构建命令名，不表示项目正在进行公网部署。

## 整栈验证

```powershell
docker compose -f compose.prod.yaml --env-file .env config --quiet
docker compose -f compose.prod.yaml --env-file .env up -d --build --wait --wait-timeout 180
docker compose -f compose.prod.yaml --env-file .env ps
```

完整质量门禁见[测试策略](测试策略.md)。

## Provider 模式

| 场景 | `PROVIDER_MODE` | 需要 Key | 预期行为 |
| --- | --- | --- | --- |
| 默认本地开发与测试 | `DEMO_ONLY` | 否 | 不发起外部调用，结果可复现 |
| 本地真实数据调试 | `REAL_ONLY` | 是 | 真实调用失败即失败 |
| 显式降级验证 | `REAL_WITH_EXPLICIT_FALLBACK` | 是 | 仅白名单错误可以回退 Demo |
| 非法模式 | 其他值 | — | 启动失败 |
| 新旧配置冲突 | `PROVIDER_MODE` 与 `DEMO_MODE` 冲突 | — | 启动失败 |

`PROVIDER_MODE` 是权威配置，`DEMO_MODE` 仅保留旧配置兼容。完整变量与 Key 分离规则见[本地运行指南](../operations/本地运行指南.md)和[Provider 集成](../architecture/Provider集成.md)。

## Windows 常见问题

### JaCoCo 路径

非 ASCII 工作区可能导致本地 JaCoCo 数据路径问题。遇到错误时把 JaCoCo 数据文件显式指向 ASCII 临时目录；Linux CI 不受此问题影响。

### pytest 临时目录权限

```powershell
uv run pytest --basetemp=.pytest-temp-clean
```

### 端口冲突

通过 `.env` 的 `WEB_PORT`、`PROMETHEUS_PORT` 及对应基础设施端口调整本地映射。更多问题见[故障排查](../operations/故障排查.md)。
