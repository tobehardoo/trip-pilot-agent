## 项目定位

TripPilot 是面向国内单城市自由行的约束驱动旅行规划系统，也是一个小型个人学习项目。它以本地 Docker Compose 为主要运行方式，默认使用不依赖外部凭据的 `DEMO_ONLY` 模式。

项目当前追求的是：在可控规模内把规划、异步任务、事件、版本、编辑、解释和跨层测试做完整。公网服务器部署、真实预订和大规模运营不属于当前目标。

## 产品定义：完整、真实、可执行

TripPilot 的核心交付物是“完整、真实、可执行的旅行计划”。

- **完整（Complete）**：多日行程应覆盖到达、离开、住宿语义、游览、餐饮、活动间交通和跨日衔接，而不是一组互不相连的景点。
- **真实（Authentic）**：POI、路线、营业时间等外部事实应保留来源和新鲜度；推导值应可解释；Demo 或估计结果必须明确标识。
- **可执行（Executable）**：硬规则决定行程是否可作为可执行计划，体验评分只评价已经可行的方案。硬校验失败应进入修复、重规划或明确失败，不能用高分掩盖不可行。

这是目标定义，不代表所有规则都已经完成。当前重复 POI和活动重叠已有硬规则；路线端点、完整跨日连续性、营业时间、时长边界和餐饮窗口仍需接入独立 Hard Validation。

## 主要用户旅程

```text
注册或登录
  -> 创建旅行并填写日期、预算、兴趣、住宿、必去/避开和固定安排
  -> 可选导入攻略或刷新城市情报
  -> 创建规划任务并查看真实阶段进度
  -> 查看带时间、交通、费用、地图和解释的多日行程
  -> 编辑活动或交通，生成新的不可变版本
  -> 比较或回滚版本
  -> 分享只读链接，或导出 PDF / ICS
```

## Demo 与真实 Provider

| 模式 | 用途 | 行为 |
| --- | --- | --- |
| `DEMO_ONLY` | 默认本地体验、开发和自动化测试 | 不调用外部 Provider；路线、费用等估计值明确标识 |
| `REAL_ONLY` | 本地显式启用真实高德/QWeather | 缺少凭据或调用失败时明确失败，不伪装成 Demo 成功 |
| `REAL_WITH_EXPLICIT_FALLBACK` | 调试真实调用与特定降级场景 | 仅允许白名单类别降级，并保留来源 |

真实 Provider 是可选增强。服务端高德 Key、浏览器 Web JS Key和 QWeather Key/Host 必须按各自用途配置，但它们不影响无凭据 Demo 主流程。

## 执行性与体验评分

行程结果应有两层独立结论：

1. **Feasibility**：硬规则校验，回答“这份行程是否可执行”。
2. **Experience Evaluation**：只评价已通过硬校验的方案，回答“体验质量如何”。

结果页已经把“我的要求”、执行性摘要和体验评分分层展示；后续需要接入更完整的 Feasibility Report、Typed Nodes、Sticky Map 和具体修复信息。

## 本地项目完成标准

以下条件共同定义本项目的目标完成状态：

1. `DEMO_ONLY` 下可通过 Docker Compose 完成创建、SSE、行程查看、编辑、回滚、分享和导出主旅程。
2. Java、Python、Web、消息契约和 Compose smoke 的本地/CI 门禁持续通过，覆盖率不低于仓库规定阈值。
3. 独立 Hard Validation 覆盖重复、重叠、路线端点、跨日连续性、营业时间、时长和餐饮窗口。
4. 住宿三态与跨日衔接能被明确建模和验证。
5. 修复或重规划是有界且可解释的，编辑后会重新验证受影响范围。
6. UI 分开展示“已验证/待修复”和体验评分，不把估计或未知事实伪装为已确认。
7. 核心 golden scenarios 与跨层测试能稳定复现主要成功和失败路径。

这些标准不要求 staging、镜像 registry digest、TLS、固定出口 IP、生产告警、备份恢复、应用回滚或 24 小时 soak。

## 非目标

- 机票、火车票、酒店库存、支付和真实预订。
- 多城市联程、多人实时协作、完整 PWA 和国际化。
- 大型爬虫平台、全局最优求解器或海量城市内容运营。
- Kubernetes、公开生产部署和企业级运维体系。

如果未来明确决定公开部署，应单独评估认证安全、隐私、TLS、Secret 管理、Provider 配额与白名单、日志脱敏、备份恢复和监控告警；不把这些未来工作混入当前本地完成标准。

## 已知限制

- 当前规划主路径是逐日贪心容量填充，OR-Tools 尚未进入主求解路径。
- 酒店、枢纽、餐厅等允许重复类型尚未形成完整规则。
- 未选择酒店时不会伪造 POI 或坐标，但 Area Estimated 和完整跨日连续性仍未完成。
- Demo 费用与路线是估计值，不代表实时供应商结果。
- 真实 Provider 依赖用户自己的账号、配额和配置。
- 出发前仍应核验营业时间、预约、票价与临时交通变化。
