# V2.5 Release Evidence

Date: 2026-07-29

## Scope accepted

- The Web AMap view no longer waits for the optional `complete` event after a
  map instance has been created. A slow or absent event therefore cannot hide a
  working map.
- A walking leg longer than 20 minutes becomes a reviewable recommended
  transit draft. The traveller can explicitly confirm it, choose another mode,
  or discard it before any version is saved.
- Multiple reviewed itinerary changes remain a local draft. One explicit
  confirmation writes one immutable itinerary version through the batch edit
  endpoint; a failed save preserves the draft for retry.
- The version panel initially shows the latest three entries and expands older
  versions only on request.

## Sample-user journeys exercised

1. A returning desktop traveller restores a session and opens a trip workspace.
2. A traveller previews an itinerary mutation before applying it.
3. A traveller makes several itinerary changes, sees the unsaved draft state,
   and saves exactly one reviewed version only after confirmation.
4. A traveller experiences an interrupted planning stream; a repeated SSE
   stage is ignored and a single final itinerary is shown.
5. A mobile share recipient opens a narrow, immutable, redacted share page.

## Acceptance boundary

This is a repository and local Compose acceptance record. Provider-side AMap
availability ultimately also depends on the configured key, security code,
quota, and the deployed browser origin. The application regression that hid a
created map instance has been removed and is covered by component tests.
