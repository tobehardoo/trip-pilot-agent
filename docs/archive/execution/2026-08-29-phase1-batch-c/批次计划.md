## 1. 契约设计（v1）

| 契约 | 方向 | envelope | payload |
| --- | --- | --- | --- |
| `AGENT_ASK_USER` | agent-service → Java（事件交换机） | eventType / schemaVersion=1 / eventId / traceId / tripId / **runId** / occurredAt | `question`(1..300 必填)、`options`(≤10 项各 1..60，可空)、`expectedType`(TEXT/NUMBER/DATE/CHOICE，可空) |
| `AGENT_RESUME` | Java → agent-service（命令） | 同上 envelope | `answer`(1..2000，用户原话，兼作 evidence-match 的证据) |

- 词汇表用 SCREAMING_SNAKE（与既有契约一致）；agent 工具层的 `expected_type` 小写值在 P2.1 发布时映射为大写。
- resume 的幂等键 = 命令自身的 `eventId`（复用 P1.6 `command_event_id` 机制），不另设字段。
- `runId` 是 envelope 字段（对应 planning 契约的 `taskId` 地位）。

## 2. 并发语义设计决策（P2.1 实施约束，本批落词汇表）

1. WAITING_USER 的 run 只能被携带其 `runId` 的 AGENT_RESUME 继续。
2. 同 trip 在 WAITING_USER 期间到达新 AGENT_START：旧 run 标记 **SUPERSEDED**（checkpoint 保留审计），新 run 以旧 checkpoint 的 slots 作初始状态 → `RunStatus` 词汇表本批加入 `SUPERSEDED`。
3. 迟到/重复的 AGENT_RESUME：`eventId` 已处理 → 幂等忽略；run 非 WAITING_USER → 按 planning 既有语义拒绝（不可重投错误 → 死信）。
