## 当前结论

项目的主要用户链路、异步事件、版本编辑、分享导出、体验评分、天气/城市情报和逐日骨架已经具备。当前阶段不再围绕“生产发布”推进，而是集中补齐影响行程真实性和可执行性的领域规则，并用本地/CI 测试锁定行为。

工程稳健性三项 P0 已关闭：

- `AGENT_INTERNAL_TOKEN` 不再回退到 `JWT_SECRET`。
- 内部诊断 Token 不再使用公开默认值，启动配置要求独立强值。
- Outbox 发布有最大重试次数和死信状态，不会无限占用发布槽位。

## 近期工作顺序

### 1. 文档与事实基线（已完成）

- 已统一本地优先定位、默认 Demo 使用方式和项目完成标准。
- 已移除活跃文档中的过期 RC/staging 门禁，历史材料保留在归档或 Git 历史。
- 长期文档不再固化容易过期的测试数量。

完成条件：新读者能只看 README、产品概述和本地运行指南启动系统，并能区分已完成、部分完成和计划中能力。

### 2. 独立 Hard Validation

- 从体验评分中分离硬校验结果。
- 在现有重复与重叠规则上补齐路线端点、跨日连续性、营业时间、时长上下界和餐饮窗口。
- 营业时间接入已完成的数据基础，保留 VERIFIED、CONFLICTING、STALE、UNKNOWN 等证据状态。
- 失败不得生成“已验证”结论，应进入待修复、重规划或明确失败。

完成条件：每项规则有领域级测试、跨层契约和可解释失败信息。

### 3. 全旅程骨架与住宿三态

- 建立跨多日的临时 Trip Skeleton 聚合。
- 住宿状态区分 `Confirmed`、`Area Estimated`、`Unresolved`。
- DAY N 结束位置与 DAY N+1 起点保持一致，编辑后重新验证受影响日期。
- 显式定义酒店、枢纽、餐厅等允许重复的实体类型。

完成条件：多日行程不依赖伪造酒店或坐标，也不会静默产生跨日断档。

### 4. Visit Duration Profile

- 把量级默认值升级为 minimum/recommended/maximum。
- 加入版本、来源和置信度，Provider 证据优先，估计值明确标识。
- 调度只能在允许范围内压缩或扩展时长。

完成条件：时长规则可被 Hard Validation 和修复逻辑共同使用。

### 5. 有界 repair / replan

- 对可修复的硬规则失败执行有限次数、有限范围的调整。
- 每次修复记录原因、改动和剩余失败项。
- 用户编辑后只重算必要范围，但最终验证覆盖所有受影响约束。

完成条件：修复不会无限循环，也不会用降级数据掩盖失败。

### 6. Feasibility UI 与 golden scenarios

- 展示“已验证/待修复”、具体规则、受影响日期和证据来源。
- 继续完善 Typed Nodes、Sticky Map 与约束满足状态。
- 建立覆盖成功、未知、冲突、过期、跨日断档和修复失败的 golden scenarios。
- 增加 Planner、Provider 与 Worker 主链的 Python 覆盖，消除只测基础模块的盲区。

完成条件：用户能理解为何可行或不可行，测试能跨层复现关键结论。

## 后续改进

| 优先级 | 项目 | 原因 |
| --- | --- | --- |
| P2 | Java 结构化日志与 traceId | 当前应用层几乎没有结构化日志，本地联调定位成本高 |
| P2 | 拆分超大服务与页面 | `ItineraryService` 和 `TripDetail.vue` 维护成本较高 |
| P2 | 浏览器级 SSE 恢复与异常旅程 | 补强真实交互回归 |
| P3 | 扩展城市知识 | 先验证知识导入到规划影响的完整链路，再扩内容 |
| P3 | LLM 文案润色 | 只能增强表达，不参与硬事实或可行性判定 |

## 当前风险

| 优先级 | 风险 | 控制方向 |
| --- | --- | --- |
| P1 | Hard Validation 覆盖不完整 | 按规则逐项接入，不以体验评分替代可行性 |
| P1 | 住宿与跨日连续性未闭环 | 先完成三态与 Trip Skeleton，再扩复杂行程 |
| P1 | 营业时间数据尚未进入完整硬门禁 | 沿用现有证据边界，避免未知或过期事实被当作硬约束 |
| P2 | Python CI 对 Planner/Provider/Worker 主链覆盖有限 | 增加跨模块与消息链路测试 |
| P2 | Java 缺少结构化日志 | 引入 SLF4J、MDC/traceId 和异常边界日志 |

## 不纳入当前路线图

- 公网服务器部署、staging 验收、镜像 registry digest、TLS 和固定出口 IP。
- 生产告警、备份恢复、应用回滚与 24 小时 soak。
- 机酒库存、支付、真实预订、多城市联程和大规模运营。

如果项目未来改变定位，应先新增 ADR 和独立发布路线图，再恢复相应门禁。
