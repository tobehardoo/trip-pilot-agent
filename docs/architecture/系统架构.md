## 1. 总体分层

```
Vue 3 Web ── REST / SSE ──→ Java 21 / Spring Boot（业务 · Outbox · SSE 透传）
                                │ 命令（PLANNING_CREATE / REPLAN / CANDIDATE_VALIDATION / CANCEL）
                                ↓ RabbitMQ
                          Python Agent Service
                            ├─ Agent 编排层（LangGraph，有界循环）
                            ├─ Tool 层（声明式 · 能力注入 · fail-closed）
                            └─ 确定性内核（确定性日排程：贪心默认 / CP-SAT 可选 shadow · 可行性校验 · Provider · pgvector）
                                │ 事件（PLANNING_COMPLETED v11 / REVIEW_REQUIRED v2 / FAILED / PROGRESS）
                                ↓ RabbitMQ
                          Java 持久化 → SSE
```

| Layer | Technology | Responsibility |
|---|---|---|
| Frontend | Vue 3, TypeScript, Vite | 对话收集约束、行程编辑、地图、版本、SSE 进度 |
| Backend | Java 21, Spring Boot, MyBatis | 业务权威、Outbox、任务状态机、SSE、幂等 |
| Agent Service | Python 3.12, FastAPI, LangGraph | Agent 编排、规划、可行性、优化、知识检索 |
| Messaging | RabbitMQ | 命令/事件异步链路（版本化契约） |
| Data | PostgreSQL, PostGIS, pgvector, Redis | 业务数据、空间/向量检索、缓存 |

## 2. 主链路（异步规划）

```
用户输入 → Java API → Transactional Outbox → RabbitMQ
  → Python Worker → Agent / Planning Pipeline → 确定性求解
  → 可行性校验（fail-closed）→ 事件回写 → Java 持久化 → SSE 推送
```

- 编辑与回滚走 `candidate-validation` 异步链，正式版本只来自 VERIFIED 候选。
- 取消为协作式：`CancellationOracle` + asyncio signal，不强杀 Worker。

## 3. Agent 化信任边界

```
┌─ Agent 决策层（LLM，有界）─────────────┐
│ 意图理解 · 约束收集 · 策略选择 · 澄清    │
└──────────────┬─────────────────────────┘
       只能提议（工具调用）
┌──────────────▼─────────────────────────┐
│ Tool 层（声明式 schema · 9 工具）       │
└──────────────┬─────────────────────────┘
       只返回事实
┌──────────────▼─────────────────────────┐
│ 确定性内核（守门）                     │
│ 确定性求解 · validate 一票否决 · 知识   │
└────────────────────────────────────────┘
```

- **LLM 负责**：理解意图、约束收集（槽位填充）、选择查什么、决定何时澄清与交棒。
- **确定性代码负责**：算路程/营业时间/预算、排班、可行性判定、终态生成。
- **三条铁律**：硬事实只来自工具（缺失返回 `UNKNOWN`，不编造）；`validate_itinerary` 一票否决；循环三重上限（MAX_STEPS=8 / MAX_TOOL_CALLS=16 / MAX_LLM_CALLS=8）。

## 4. 记忆分层

| 层 | 内容 | 载体 |
|---|---|---|
| Working | 单次运行内约束槽位、工具观测、待澄清项 | AgentState + checkpoint（Redis 短 TTL） |
| Episodic | 决策轨迹（审计、回放、恢复） | `agent_run` / `agent_step`（规划中） |
| Semantic | 攻略事实、城市情报、向量知识 | pgvector + retrieval（已有） |
| Profile | 跨会话用户偏好（用户确认后生效） | `user_travel_profile`（规划中） |

约束槽位三态：`UNKNOWN` → `INFERRED` → `CONFIRMED`；**只有 CONFIRMED 进入 TripConstraints**，INFERRED 仅作软偏好（fail-closed 记忆）。

## 5. 关键工程特性

- **可靠异步**：Outbox + RabbitMQ 驱动，事件回写 + SSE。
- **不可变版本**：编辑/回滚形成新版本，支持 diff 与回滚。
- **幂等**：确定性 event_id + 任务级幂等键，重试可复现（ADR-012）。
- **契约版本化**：事件契约 schema_version 演进，历史事件只读兼容（ADR-014）。
- **Fail-closed 可行性**：数据不确定时显式 UNKNOWN / UNRESOLVED，不伪造成功。
