## 当前阶段：工程稳健性修复

基于全项目审计报告的发现，修复本地开发中实际受影响的三项问题。

| 编号 | 问题 | 影响 | 状态 |
| --- | --- | --- | --- |
| P0-1 | `AGENT_INTERNAL_TOKEN` 回退到 `JWT_SECRET` | 两种凭据不应复用，compose 默认配置下存在风险 | 进行中 |
| P0-2 | 诊断 token 默认值 `local-development-only` | 非 compose 直启时 token 退化为公开已知值 | 进行中 |

## 下阶段计划

下阶段里程碑围绕"完整、真实、可执行"收敛，权威口径见[行程真实性与旅行骨架](../architecture/行程真实性与旅行骨架.md)。

### 骨架：全旅程 Trip Skeleton

- 建立跨全旅程的临时领域聚合，连接每日骨架与住宿语义。
- 将当前“普通景点不跨日重复”扩展为显式允许重复规则（酒店/枢纽/餐厅）和住宿三态。
- 将当前 Unresolved 节点纳入全旅程连续性，并补齐 Area Estimated。

### 验证：独立 Hard Validation

- 从 Evaluator 分离出独立硬校验层：重复 POI、端点、跨日连续性、重叠、开放时间、时长上下界、餐饮窗口。
- 失败进入修复/重规划/失败终态，不产生成功 PlanEvaluation。
- UI 已分开展示"行程可执行：已验证"与"体验评分"；后续接入真实 Feasibility Report 的“待修复”状态。

### 时长：Visit Duration Profile

- 把固定量级默认值升级为 minimum/recommended/maximum + provenance + confidence 的版本化画像。
- Provider 时长证据优先，Agent 建议只做带置信度的补充，Optimizer 在界内调整。

### 跨日：连续性硬门禁

- DAY N 末节点必须能到达过夜锚点，DAY N+1 从同一住宿状态开始。
- 局部编辑破坏连续性时的影响范围重新验证。

### 结果页：继续完善双层展示与共享约束

- 已完成顶部“我的要求”、执行性/体验分层和共享 ConstraintEditor。
- 后续补齐 Typed Nodes、Sticky Map、约束满足状态，并将攻略/Provider 技术信息进一步降级折叠。

### 兼容性：契约与历史

- 以 completion v8 为事实基线；进度阶段（95%）与完成事务边界收敛。
- 历史版本只读保留原评分，不追溯重算。
- 旧版已完成行程的展示兼容（缺失 evaluation 返回 null）。

### Java 服务端日志接入

**要做的事**：引入 SLF4J、加 traceId 过滤器、在 `GlobalApiExceptionHandler` 中记录异常。

**学习价值**：结构化日志设计、MDC 上下文传播、运维可观测性基础。

### 扩展城市与补齐测试

**要做的事**（待讨论后确定）：
- 写新的城市知识 Markdown，走通攻略导入 → 事实抽取 → 规划影响链路。
- 按[测试策略](../development/测试策略.md)的旅行真实性验收矩阵补齐 golden scenarios。
