## 1. 事件族设计（克制版）

| 事件 | 方向 | 载荷 | 发布时机 |
| --- | --- | --- | --- |
| `AGENT_ASK_USER` | worker → Java | question / options / expectedType | run 以 WAITING_USER 收敛后（P1.8 已有，P2.1 已发布） |
| `AGENT_STEP`（7a 新增） | worker → Java | seq（回合内 0 起）/ tool / ok / summary / errorCode | sink 检测到新工具观测时逐条发布（上限 = MAX_TOOL_CALLS=16/回合）；**`ask_user` 观测不入 STEP 流**——AGENT_ASK_USER 事件是其载体，重复 step 只会加噪 |
| `AGENT_COMPLETED`（7a 新增） | worker → Java | summary / itinerary（完整 wire 对象） | 自动发射（EMITTED）后 |

**克制决策（对路线图事件清单的偏离，记录在案）**：不发布 `AGENT_THINKING`——决策 thought 不在 run 状态里，为其单独落事件不满足三问（前端进度已由 TOOL 步覆盖，原始思考走轨迹查询 API）。若 P2.8 的对话页证明需要"正在思考"指示，以 AGENT_STEP 的 THINKING kind 扩展（同 schema 加枚举），不改事件族。

- 路由键：`agent.ask-user` / `agent.step` / `agent.completed`（trip.event.exchange）。
- Java 消费侧（7b）：单队列 `agent.dialog.event.queue` 绑定三键、按 eventType 分派（家族小，合队列；与 planning 每族一队列的差异记录在案）、落 `business.agent_dialog_message`、SSE hub 镜像 `PlanningTaskEventHub`。
