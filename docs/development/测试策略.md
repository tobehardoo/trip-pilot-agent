## 目标

测试服务于本地项目的两个核心结论：主要用户旅程可以稳定运行，规划结果不会把未知、冲突或不可行状态伪装成成功。真实 Provider 是可选验证，不是普通测试的依赖。

文档不长期保存容易过期的“通过多少项”数字；当前结果以本地命令和 CI run 为准。

## 本地完整门禁

### Java

```powershell
mvn --batch-mode -pl apps/travel-server clean verify
```

覆盖单元/集成测试、Flyway 迁移验证和 JaCoCo。

### Python

```powershell
cd apps/agent-service
uv sync --extra dev
uv run pytest
uv run ruff check .
uv run python benchmarks/run_plan_evaluation.py
```

默认测试使用 Demo 或 fixture，不调用真实 Provider。

### Web

```powershell
cd apps/web
corepack enable
pnpm install --frozen-lockfile
pnpm test:coverage
pnpm typecheck
pnpm build
pnpm test:e2e
```

### 契约、脚本与基础设施

```powershell
python -m unittest discover -s scripts/tests -p 'test_*.py' -v
python -m ruff check scripts/
docker compose -f compose.prod.yaml --env-file .env config --quiet
docker compose -f compose.prod.yaml --env-file .env build
```

如本机安装了 gitleaks，再运行：

```powershell
gitleaks detect --source . --verbose
```

## 门禁原则

- **零失败**：相关套件全部通过，不通过删除测试换取绿色结果。
- **覆盖率不下降**：继续满足仓库现有门槛；新增关键路径必须有测试。
- **契约一致**：消息 Schema、Python 模型和 Java parser/持久化使用共享 fixture 验证。
- **迁移可前向执行**：Flyway 全链必须能在干净数据库完成。
- **Demo 可复现**：无 Key 环境能稳定覆盖主旅程。
- **失败语义可见**：Provider、Hard Validation、消息消费和编辑冲突不能变成伪成功。

## 真实 Provider 测试

默认跳过真实 Provider，避免网络波动和配额改变普通门禁：

```powershell
$env:RUN_REAL_PROVIDER_TESTS="true"
uv run pytest
```

这类测试用于确认本机 Key、适配器和第三方响应，不能替代 fixture、契约或领域测试。结果不得泄露 Key、完整请求/响应或用户数据。

## 核心浏览器旅程

Playwright 应持续覆盖：

1. 会话创建与恢复。
2. 创建规划、真实 SSE 阶段和终态覆盖。
3. 编辑预览、草稿确认与不可变版本。
4. 版本差异和回滚。
5. 只读分享、PDF/ICS 导出。
6. 评估、天气日期与地图过滤组合链路。

具体用例数量可以变化，只要上述行为没有失去覆盖。

## 旅行真实性验收矩阵

以下 golden scenarios 是近期补齐重点：

| 场景 | 核心断言 | 主要层级 |
| --- | --- | --- |
| 单日游 | 到达、活动/餐饮/交通、离开顺序合理；无过夜不强制住宿 | Python 规划 |
| 多日游 | 住宿状态连接相邻日期，末日离开优先 | Python 规划 + Hard Validation |
| 晚到/早离 | 可用窗口缩短时不强塞活动 | Python 规划 |
| 无酒店/区域住宿 | 使用明确的 Unresolved/Area Estimated，不伪造酒店 POI | 规划 + 版本模型 |
| 重复 POI | 禁止的跨日重复被拒绝或修复，允许重复类型不误报 | Hard Validation |
| 营业时间 | VERIFIED 可参与判断；CONFLICTING/STALE/UNKNOWN 不产生伪硬结论 | Evidence + Hard Validation |
| 餐饮与时长 | 硬窗口和上下界失败可解释，推荐值只影响体验 | Validation + Evaluation |
| 修复循环 | 修复次数和范围有界，失败后不持久化伪成功版本 | Planner + Worker + Java |
| N/A 评分 | 无预算/兴趣时显示未适用并正确归一化 | Evaluation + Web |
| 完成进度 | 95% 进度由独立完成/失败事件收尾 | Worker + Java + Web |

| Job | 主要内容 |

这些 Job 是代码质量门禁，不代表服务器部署或公开发布已经完成。

## 已知测试盲区

- Python CI 的覆盖率统计目前集中在 retrieval、acquisition 和 guide intelligence 等指定模块；Planner、Provider 与 Worker 主链需要更完整的覆盖率与跨模块测试。
- 完整 Hard Validation、住宿三态、有界 repair/replan 的 golden scenarios 尚未全部实现。
- 真实公交路线和更多城市的真实 Provider 行为尚未系统验证。
- 浏览器主链已有覆盖，但故障注入、SSE 异常恢复和移动端组合旅程仍可加强。
- Windows 的非 ASCII JaCoCo 路径和 pytest 临时目录权限可能需要本机规避；见[本地开发指南](本地开发指南.md)。
