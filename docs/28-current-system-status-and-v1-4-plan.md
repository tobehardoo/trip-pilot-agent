## 1. 结论

V1.3 的代码、数据库迁移、自动化测试、生产镜像和本地全栈运行门禁已经完成。系统现在
具备可信城市来源、自动预热、TTL/stale 降级、不可变规划上下文、事实影响解释，以及
行程版本列表、差异和幂等回滚。

唯一尚不能由仓库自行完成的退出项是真实高德 Web JS 底图授权：当前环境未配置
`VITE_AMAP_WEB_JS_KEY` 与 `VITE_AMAP_SECURITY_CODE`。真实浏览器已验证缺少凭据时页面
保留路线概览并给出明确诊断，但不能把该降级结果当作真实图块成功。结构化模型和真实
高德 Web Service 同样是可选外部凭据；缺失时系统保留可追踪降级，不伪造 Provider 成功。

## 2. 已交付数据流

```text
创建旅行
  → 同一事务写预热记录与 Outbox
  → RabbitMQ 消费者幂等刷新高德与已审核官方来源
  → Python 规范化、规则/受限模型候选、Schema/证据校验
  → Java 持久化事实、来源、生命周期与刷新诊断

创建规划任务
  → 按类别、日期与 TTL 检查，限时等待必要刷新
  → 失败时保留最后成功事实并标 stale
  → 官方/Provider/社区冲突决策
  → 冻结 PlanningContextSnapshot V3
  → Worker 只消费快照并输出 PlanningFactImpact
  → Java 创建不可变行程版本并持久化解释

查看或恢复行程
  → 列出不可变版本
  → 计算活动、交通和事实影响的结构化差异
  → 幂等回滚创建新的 ROLLBACK 版本
  → 历史版本保持不变
```

## 7. 外部阻塞和降级

- 真实底图成功必须由部署者配置同一高德应用的 Web JS Key、安全密钥和域名白名单。
- 真实 POI、路线、天气与景点 Provider 需要 Web Service Key；无 Key 时 Demo/陈旧事实
  必须带来源标记。
- 官方站点可能限流或改变页面；刷新失败记录诊断并保留最后成功事实，不绕过登录或
  反自动化限制。
- 结构化模型未配置、超时或违反 Schema 时，规则抽取继续且模型状态为
  `SKIPPED/FAILED`。
