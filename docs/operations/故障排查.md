## 常见问题

### Docker Compose 启动失败

**症状：** `compose up` 后服务无法健康启动。

**排查步骤：**

1. 检查 Docker Desktop 是否运行。
2. 检查端口冲突：`8080`（Web）、`9090`（Prometheus）、`5432`（PostgreSQL）、`6379`（Redis）、`5672`（RabbitMQ）。
3. 检查 `.env` 中的密钥是否已从 `.env.example` 的占位值替换。
4. 检查可用内存是否达到 8 GB。
5. 查看各服务日志：
   ```powershell
   docker compose -f compose.prod.yaml --env-file .env logs <service-name>
   ```

### 知识初始化失败

**症状：** `knowledge-init` 容器非零退出码。

**排查步骤：**

1. 检查 PostgreSQL 是否已健康启动。
2. 检查 Flyway 迁移是否成功（查看 knowledge-init 日志中的 Flyway 输出）。
3. 检查 `knowledge/` 目录下的知识文件是否完整。

### 规划任务失败

**症状：** 创建规划后任务快速失败或超时。

**排查步骤：**

1. 检查任务状态和错误信息：
   ```http
   GET /api/planning-tasks/{taskId}
   ```
2. 检查 `errorCode` 和 `errorCategory` 字段。
3. 查看 Worker 日志中的错误详情。
4. Demo 模式下检查城市知识是否已导入。
5. 真实模式下检查 Provider Key 是否有效。

常见错误码：
- `NO_FEASIBLE_ITINERARY`：约束不可满足，检查预算、必去地点和固定安排是否冲突。
- `PROVIDER_ERROR`：Provider 调用失败，检查 Key 和网络连通性。
- `DATA_QUALITY_ERROR`：数据质量问题，硬约束违规。

### SSE 连接断开

**症状：** 浏览器规划进度停止更新。

**排查步骤：**

1. 刷新页面，SSE 会自动通过 `Last-Event-ID` 恢复。
2. 检查浏览器网络面板中的 EventSource 连接状态。
3. 检查 Java 服务是否正常运行。

### 行程编辑冲突

**症状：** 编辑行程返回 `409 ITINERARY_VERSION_CONFLICT`。

**原因：** 其他操作已修改了当前版本。

**解决方法：**

1. 刷新页面获取最新版本。
2. 重新进行编辑操作。
3. 如果是幂等键冲突（`409 IDEMPOTENCY_KEY_CONFLICT`），说明相同 key 发送了不同请求，需要生成新 key。

### 真实 Provider 验收失败

**症状：** `REAL_ONLY` 模式下规划返回 Demo 结果或无结果。

**排查步骤：**

1. 确认 `PROVIDER_MODE=REAL_ONLY`（不是 `DEMO_ONLY`）。
2. 确认 `AMAP_WEB_SERVICE_KEY` 已配置且有效。
3. 确认无 `DEMO_MODE` 旧配置冲突。
4. 检查 Worker 日志中的 Provider 错误详情。
5. 在高德控制台检查 Key 配额和 IP 白名单。

### RabbitMQ 队列积压

**症状：** 队列中消息数持续增长。

**排查步骤：**

1. 检查 Worker 是否在运行：
   ```powershell
   docker compose -f compose.prod.yaml --env-file .env ps worker
   ```
2. 检查 Worker 日志是否有异常。
3. 检查死信队列中的消息。
4. 确认消息格式是否与当前 Schema 版本兼容。

### 数据库连接问题

**症状：** Java 服务无法连接 PostgreSQL。

**排查步骤：**

1. 确认 PostgreSQL 容器正在运行且健康。
2. 检查 `.env` 中的 `POSTGRES_PASSWORD` 是否正确。
3. 检查端口是否被占用。

### Windows 特定问题

#### JaCoCo 路径错误

**症状：** Maven 构建时 JaCoCo 报告路径相关错误。

**解决方法：** 显式指定 ASCII JaCoCo 数据路径。Linux CI 不受影响。

#### pytest 临时目录权限

**症状：** pytest 运行出现 fixture setup error。

**解决方法：** 使用明确隔离的临时目录：
```powershell
uv run pytest --basetemp=.pytest-temp-clean
```

## 诊断入口

受保护诊断 API（需要 `INTERNAL_DIAGNOSTICS_TOKEN`）：

- 查看失败任务上下文。
- 对安全失败任务执行幂等重试。

诊断入口只暴露脱敏信息，不暴露敏感数据。

## 恢复演练清单

| 场景 | 预期结果 |
| --- | --- |
| RabbitMQ 重启 | 队列恢复 durable 配置，各有消费者且 ready/unacked 为 0 |
| Worker 暂停后恢复 | `planning.create.queue` 保留消息，Worker 恢复后成功完成任务 |
| Java Consumer 暂停后恢复 | `planning.completed.queue` 保留消息，Java 恢复后继续持久化 |
| Redis 清空后重启 | 只清除缓存；PostgreSQL 核心数据计数不变 |
| 整栈重启 | 全部长期服务健康，`knowledge-init` 退出码为 0 |
| 重复完成事件 | 只产生一个版本/终态事件 |
