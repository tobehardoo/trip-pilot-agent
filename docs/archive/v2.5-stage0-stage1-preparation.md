## 真实 Provider 验收执行卡

前提：所有准入项完成，且使用专用预生产数据库、Redis、RabbitMQ 与独立 AMap 配额。

1. 执行 Compose 健康检查：

   ```powershell
   docker compose -f compose.prod.yaml --env-file .env up -d --wait --wait-timeout 180
   docker compose -f compose.prod.yaml --env-file .env ps
   ```

2. 以受控账号创建 1 日、2 日、3 日行程，分别覆盖必去地点、固定日程和到达/离开点。
3. 验证完成事件、活动来源和路线来源均为 `AMAP`，并保存脱敏事件与地图截图。
4. 分别演练超时、429、5xx、认证失败、配额耗尽和协议异常：
   - 瞬时错误：确认降级结果为 `DEMO`，并有 `planning_provider_fallback` 日志。
   - 永久错误：确认 V2 `PLANNING_FAILED` 到达 Java、任务进入失败终态且 SSE 只出现一次。
5. 搜索发布日志和事件载荷，确认没有 AMap Key、Token、Cookie 或完整敏感 URL。
6. 保存任务 ID、trace ID、时间、错误码、截图和队列状态；完成后关闭临时环境。
