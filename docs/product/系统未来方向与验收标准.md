### 2.1 近期（Release-to-main 收尾）— 已完成（2026-08-21）

### 2.2 中期（B19 系列既定 follow-up，可推 main 之后）

按 B19-C/B19-D 已记录的 Known Gaps，按序推进：

1. **manual edit TRANSIT 真实化**：planner 生成的 TRANSIT 已是真实 AMAP；manual-edit TRANSIT 仍为 DEMO/local estimate，需接入 `candidate-validation → AMap TRANSIT → completion → Java version` 闭环（QA-D09）。
2. **D1 polyline 硬化复核**：`_amap_transit.py` 已硬化（空段跳过/OD fallback/畸形 fail-closed）；但 `_amap_transit_models.py` 的 `_empty_segment_array_to_none` 仍会把**非空畸形数组**当缺失 → fallback 成功，需 fail-closed（用户审计 P2）。
3. **模式语义收敛复核**：TAXI/AUTO/DRIVING 在编辑、版本、分享、导出、PDF/ICS 全渠道一致；Web 无本地 AUTO 推荐。
4. **跨城/跨区域 TRANSIT**：当前 TRANSIT 依赖 city 上下文，跨城 OD 需明确降级策略。

### 2.3 远期（新能力，均需独立批次计划）

以下能力**当前明确不属于** v1 范围，进入前须新建 plan 并过独立验收：

1. **Road / Taxi / Self-driving 完整语义**：`ROAD`、`SELF_DRIVING`、`roadIntent`、`vehicleAccess` 等枚举与持久化模型；不引入 completion v12。
2. **用户交通偏好**：如偏好换乘少/时间短/票价低，进入 ordered-rule 或权重，需重新校准 Golden。
3. **天气/行李输入**：天气推荐、行李负担模型；跨 mode 比较目前明确禁止票价 vs 过路费，需先定语义。
4. **Feasibility override / mode oscillation 治理**：TRANSIT 使 fixed-slot 不可行时的重试策略（v1 明确不实现，未来单独批次）。
5. **全局 mode 优化（OR-Tools 级）**：跨 leg 联合优化，替代逐 leg ordered rules。
6. **共享/协作者权限**、多用户行程协作。

## 4. 完整系统（GA v1.0）验收标准

定义：当系统达成 §3 全部门禁，且下列能力全部**实现并独立验收通过**时，方可称为完整系统（GA）。以下为验收清单，每条须有自动化测试或可复现证据。

### 4.1 功能完整性

| 领域 | 验收标准 |
|---|---|
| 规划核心 | 单日/多日行程；WALKING/TRANSIT/DRIVING 三种模式由真实 provider facts 驱动；ordered-rule 推荐可解释（reason enum）；Golden G1–G8 全过 |
| 行程编辑 | MOVE/时间/模式（WALKING/TRANSIT/TAXI/AUTO）编辑；candidate preview → validate → commit 异步链；幂等重放；stale baseline 拒绝；无部分版本 |
| 手动 TRANSIT | manual-edit TRANSIT 使用真实 AMAP（非 DEMO estimate），持久化/展示/分享/导出一致 |
| 版本管理 | immutable version；diff/rollback；正式版本只来自 VERIFIED candidate；历史报告 null 显示正确 |
| 时间语义 | fixed slot/capacity repair；跨午夜与时间边界；selected route duration 真实进入 forward-fit；95% 不卡死 |
| 输出渠道 | 编辑页/版本页/Review/分享/PDF/ICS 的 mode 文案与费用一致（persisted DRIVING 显示"打车"） |
| 评估与证据 | evaluation 必填；营业时间/知识证据进入 planning evidence；N/A 评分显示 |
| 数据模型 | 请求模型（TAXI/AUTO）与持久化模型（WALKING/TRANSIT/DRIVING）正确区分；无 v12 泄漏 |

### 4.2 可靠性

| 门禁 | 验收标准 |
|---|---|
| 故障恢复 | RabbitMQ 停机/恢复 outbox 重投；worker kill/restart 任务恢复；consumer pause 恢复；无重复正式版本、无部分写入、无无限重试、无静默丢消息 |
| 非法输入 | 非法消息 reject/DLQ 不卡队列不崩溃；畸形 provider 响应 fail-closed |
| 95% 门禁 | 规划必须从 95% 正常进入终态（SUCCEEDED/WAITING_USER/FAILED/CANCELLED） |
| 幂等 | 同 idempotency key 重放返回同一任务/版本；并发同 key 仅一次外部调用（F7） |

### 4.3 性能与稳定性（DEMO_ONLY 基线，无编造 SLA）

| 指标 | 记录项 | 必失败项 |
|---|---|---|
| API latency | p50/p95/p99 | —（报告基线，不编阈值） |
| 规划完成时间 | p50/p95 | 任务永久卡住 |
| 并发 | 10 并发基础流程；10 并发规划；S099 100 任务 | 丢失 completion、重复正式版本、非预期 5xx |
| soak | 30 分钟 | 持续增长队列积压、明显内存泄漏、服务崩溃不恢复 |

### 4.4 安全

| 门禁 | 验收标准 |
|---|---|
| 鉴权 | 未认证访问拒绝；过期/伪造/错误签名 JWT 拒绝 |
| 越权 | 跨用户读/编辑/rollback/share 均拒绝（如 S007 versions=404） |
| 内部 API | Agent 内部 token 缺失/错误拒绝 |
| 输入校验 | 超长字段/非法 enum/非法坐标日期/wire TAXI 拒绝 |
| 泄漏 | 响应/日志无凭据；CORS/Cookie Secure/SameSite 正确；分享链接权限正确 |
| 限流 | nginx auth 10r/m+burst5 等既定行为锁定并有测试 |
