## 1. 设计

| 项 | 设计 |
| --- | --- |
| 构建缝 | `ToolRuntime.itinerary_builder` 新能力缝：`builder(slots=, trip_id=) -> Itinerary`；缺省 fail-closed（CAPABILITY_MISSING）。缺必填槽位 → `INCOMPLETE_CONSTRAINTS` |
| 候选行程 | `AgentState.candidate_itinerary`（wire dict，JSON 安全）+ `AgentState.trip_id`（run 上下文）；`AgentRunResult.itinerary` 回传调用方 |
| D4 守门 | `validate_itinerary` 改为校验**候选行程对象**：无候选 → `NO_CANDIDATE`；报告 `has_blocker` → `FEASIBILITY_BLOCKED`，run 继续（LLM 可重试/追问）；通过 → 见下 |
| D3 自动发射 | 工具表**移除** `emit_itinerary`（7→8 仍为 8 个工具：emit 出、build 进）；`_act_node` 中 validate 通过即确定性置 `stop_reason=EMITTED`——发射是编排层行为，模型无发射工具 |
| Demo builder | `agent/itinerary_builder.py`：日期规范化（ISO / M月D日，无年份按今年、过期顺延一年）→ `PlanningCreateCommand`（schemaVersion 2）→ `DemoPlanningProvider.plan` → Itinerary。**不可规范化值 fail-closed**（INVALID_CONSTRAINT_VALUES / PLANNING_INFEASIBLE）；规划器必填枚举（traveler_type/pace/mobility）用中性默认值——demo 骨架不消费，真实 provider builder 后续要求规范化值 |
| 默认守门 | `agent/feasibility_gate.py`：`StructuralFeasibilityGate`——重构 Itinerary（pydantic 内建结构校验）+ 语义补查（空天、活动时序）。**窄于管线 Hard Validation 11/11 规则集**，差距文档化；Java 命令路径仍以管线内守门为权威 |
