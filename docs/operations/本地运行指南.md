## 适用范围

本文档说明如何在一台开发电脑上运行 TripPilot 的完整主链。默认使用 `DEMO_ONLY`，不需要高德、QWeather、域名、TLS、镜像仓库或服务器。

`compose.prod.yaml` 是现有 Compose 文件名，不代表项目要求生产部署；本项目将它作为本地整栈编排使用。

## 前置条件

- Docker Desktop 或 Docker Engine
- Docker Compose v2
- 建议至少 8 GB 可用内存
- 可用端口：Web `8080`、Prometheus `9090`；数据库和中间件端口按 `.env.example` 配置

## 第一次启动

### 1. 创建本地环境文件

PowerShell：

```powershell
Copy-Item .env.example .env
```

Linux/macOS：

```bash
cp .env.example .env
```

`.env` 只用于本机，不要提交。至少替换以下值：

```dotenv
POSTGRES_PASSWORD=your-local-postgres-password
REDIS_PASSWORD=your-local-redis-password
RABBITMQ_PASSWORD=your-local-rabbitmq-password
JWT_SECRET=your-random-secret-at-least-32-bytes
AGENT_INTERNAL_TOKEN=your-distinct-random-internal-token
INTERNAL_DIAGNOSTICS_TOKEN=your-distinct-random-diagnostics-token

PROVIDER_MODE=DEMO_ONLY
REFRESH_COOKIE_SECURE=false
```

三个应用令牌/密钥应使用互不相同的随机值。`AGENT_INTERNAL_TOKEN`、`INTERNAL_DIAGNOSTICS_TOKEN` 和 `JWT_SECRET` 不可复用。

### 2. 启动完整系统

```powershell
docker compose -f compose.prod.yaml --env-file .env up -d --build --wait --wait-timeout 180
docker compose -f compose.prod.yaml --env-file .env ps
```

首次启动会构建应用镜像、创建本地数据卷，并由 `knowledge-init` 完成数据库迁移和随仓库提供的知识导入。

### 3. 访问

- Web：`http://127.0.0.1:8080`
- Prometheus（可选）：`http://127.0.0.1:9090`

端口可通过 `.env` 中的 `WEB_PORT` 和 `PROMETHEUS_PORT` 调整。

## Demo 主旅程

在 `PROVIDER_MODE=DEMO_ONLY` 下应能完成：

1. 注册或登录。
2. 创建旅行并填写约束。
3. 发起规划并观察 SSE 进度。
4. 查看行程、地图、交通、天气和解释。
5. 编辑活动或交通并创建新版本。
6. 比较或回滚版本。
7. 创建只读分享，导出 PDF 或 ICS。

Demo 路线、费用和部分外部事实是确定性估计值，界面和数据来源应明确标识；它们不代表实时供应商结果。

## 日常操作

### 查看状态和日志

```powershell
docker compose -f compose.prod.yaml --env-file .env ps
docker compose -f compose.prod.yaml --env-file .env logs -f
```

查看单个服务：

```powershell
docker compose -f compose.prod.yaml --env-file .env logs -f agent-service
```

### 停止但保留数据

```powershell
docker compose -f compose.prod.yaml --env-file .env down
```

数据库、队列和缓存数据默认保留在 Docker Volume 中。

### 重新构建

```powershell
docker compose -f compose.prod.yaml --env-file .env up -d --build --wait --wait-timeout 180
```

### 清空本地演示数据

以下命令会删除本项目 Compose 创建的数据卷，只在确认不需要现有本地数据时执行：

```powershell
docker compose -f compose.prod.yaml --env-file .env down -v
```

## 可选：使用真实 Provider

真实 Provider 只用于拥有合法凭据时的本地增强或调试。把 `.env` 调整为：

```dotenv
PROVIDER_MODE=REAL_ONLY
AMAP_WEB_SERVICE_KEY=your-server-side-amap-key
QWEATHER_API_KEY=your-server-side-qweather-key
QWEATHER_API_HOST=your-dedicated-qweather-api-host
VITE_AMAP_WEB_JS_KEY=your-browser-amap-key
VITE_AMAP_SECURITY_CODE=your-browser-security-code
```

注意：

- 服务端高德 Web Service Key 和浏览器 Web JS Key 用途不同，不应混用。
- QWeather Host 使用控制台为账号分配的 HTTPS Host。
- `REAL_ONLY` 缺少凭据或调用失败时应明确失败，不会静默返回 Demo 成功。
- `REAL_WITH_EXPLICIT_FALLBACK` 只用于验证显式降级策略；允许降级的错误类别由白名单控制。
- 真实凭据始终留在本机 `.env`，不得写入文档、日志或提交。

详细语义见[Provider 集成](../architecture/Provider集成.md)。

## 启动后检查

```powershell
docker compose -f compose.prod.yaml --env-file .env config --quiet
docker compose -f compose.prod.yaml --env-file .env ps
```

检查要点：

- 长期运行服务为 healthy/running。
- `knowledge-init` 成功退出。
- Web 可以访问并完成登录。
- Demo 规划能进入终态，刷新页面后任务和行程仍可读取。

如启动或规划失败，先查看[故障排查](故障排查.md)。需要修改代码时转到[本地开发指南](../development/本地开发指南.md)。

## 当前不要求的事项

本地运行不要求 staging、registry digest、TLS、固定出口 IP、生产告警、备份恢复、应用回滚或 24 小时 soak。历史部署材料可在[归档索引](../archive/README.md)中查阅，但不是当前操作手册。
