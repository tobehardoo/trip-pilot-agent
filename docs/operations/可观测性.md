## 定位

本项目的可观测性首先服务于本地调试和自动化验证。健康检查与 Prometheus 随 Compose 提供；外部告警平台、长期日志存储和生产值班不属于当前完成条件。

## 健康检查

| 服务 | 端点或方式 | 用途 |
| --- | --- | --- |
| Java API | `GET /api/health` | 检查应用及依赖状态 |
| Agent API | `GET /health` | 检查 Python API 存活 |
| Web | `GET /` | 检查本地 Web 入口 |
| Prometheus | `GET /-/healthy` | 检查可选指标服务 |
| Compose | `docker compose ... ps` | 查看容器健康与一次性任务结果 |

`knowledge-init` 是一次性任务，成功退出表示迁移和知识初始化完成。

## Prometheus（可选）

本地默认地址为 `http://127.0.0.1:9090`，端口由 `PROMETHEUS_PORT` 调整。可用于观察：

- 规划任务成功、失败和取消。
- 规划阶段耗时和 Provider 结果。
- HTTP 请求、JVM 与队列相关指标。
- RabbitMQ ready/unacked 数量和任务终态分布。

Prometheus 不影响 Demo 主旅程；资源不足时可只使用健康检查和容器日志排查。

## 日志现状与规则

规划管线（Java 8 个关键边界 + Python Worker 边界）已落地结构化日志。Java 使用 SLF4J + MDC，经 `PlanningLogContext`（`planning` 包）在 listener 入口填充、`finally`/try-with-resources 中恢复，嵌套作用域安全，线程复用不串 `taskId`/`traceId`。Python 使用标准 `logging` + `LoggerAdapter`，字段经 `extra` 落到 `LogRecord` 属性，测试以 `caplog.records` 断言。字段名 Java 用 camelCase、Python 用 snake_case，语义对齐。

### 统一字段（非敏感关联标识）

| 字段（Java / Python） | 含义 |
| --- | --- |
| `traceId` / `trace_id` | 一次规划请求的追踪标识 |
| `eventId` / `event_id` | 事件标识 |
| `taskId` / `task_id` | 规划任务标识 |
| `tripId` / `trip_id` | 旅行标识 |
| `runId` / `run_id` | Agent 运行标识 |
| `taskType` / `task_type` | CREATE / REPLAN / EDIT_VALIDATE / ROLLBACK_VALIDATE |
| `candidateType` / `candidate_type` | EDIT / ROLLBACK |
| `schemaVersion` / `schema_version` | 事件 schema 版本 |
| `eventType` / `event_type` | 事件类型 |
| `outcomeStatus` / `outcome_status` | SUCCEEDED / WAITING_USER / FAILED |
| `attemptIndex` / `attempt_index` | repair 轮次（1–3） |
| `provider` | 实际 Provider 标识 |
| `operation` | Provider 操作（PLANNING/REPLANNING/ROUTE/…） |
| `retryable` / `retryCount` / `fallbackAttempted` / `fallbackSucceeded` | 重试与回退元数据 |

日志事件（非穷尽）：message received / contract rejected / duplicate ignored / stale baseline rejected / candidate queued / task queued / version persisted / review persisted / task completed / task failed / outbox sent / outbox rescheduled / outbox dead。

Provider 回退使用稳定事件名 `planning_provider_fallback`，记录操作、原因、重试次数和关联 ID。

### 禁止记录

- JWT、Cookie、Authorization、内部 Token、数据库 URL 凭据、密码。
- AMap、QWeather 或其他服务 Key。
- 完整 Provider 请求/响应（原始 body 一律不落日志）。
- 完整 evidence / raw statement / URL 查询参数 / 用户自由文本约束全文。
- 可能包含以上内容的未脱敏异常上下文（异常只记录安全 code/category/class 名）。

## 诊断与失败消息

受 `INTERNAL_DIAGNOSTICS_TOKEN` 保护的内部诊断入口用于：

- 查看失败任务的脱敏上下文。
- 对允许重试的失败任务执行幂等重试。

RabbitMQ 死信队列保存无法正常消费的消息。Transactional Outbox 在达到最大尝试次数后会标记 dead，避免毒消息无限占用发布槽位。排查时应区分“业务规划失败”“消息消费失败”和“Outbox 发布失败”。

## 本地观察清单

| 场景 | 建议观察 |
| --- | --- |
| 规划卡住 | Worker 日志、任务状态、RabbitMQ ready/unacked、SSE 最后阶段 |
| Provider 失败 | mode、operation、安全错误分类、retry count、是否显式 fallback |
| 完成未展示 | completion 消息、Java 消费、版本记录、SSE 终态 |
| 重复版本 | messageId、幂等记录、任务与版本数量 |
| 启动失败 | Compose health、`knowledge-init` 退出码、数据库迁移日志 |

## 可选告警示例

如果开发者自己接入本地或个人告警工具，可关注服务离线、队列持续增长、规划失败率和 Provider 连续失败。这些是调试建议，不是项目合并或完工门槛。
