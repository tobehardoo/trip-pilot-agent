## 概述

TripPilot 使用 Docker Compose 作为默认运行方式。当前生产拓扑一次性启动 PostgreSQL、Redis、RabbitMQ、Spring Boot、Agent API、Worker、Web、Prometheus 和知识初始化任务。

## 环境要求

- Docker Desktop 或 Docker Engine
- Docker Compose v2
- 建议至少 8 GB 可用内存
- 生产环境必须具备 HTTPS 终止、密钥管理和日志留存策略

## 最小配置

从 `.env.example` 复制 `.env`，至少替换：

### 基础密钥

| 变量 | 说明 |
| --- | --- |
| `POSTGRES_PASSWORD` | PostgreSQL 密码 |
| `REDIS_PASSWORD` | Redis 密码 |
| `RABBITMQ_PASSWORD` | RabbitMQ 密码 |
| `JWT_SECRET` | JWT 签名密钥，至少 32 字节随机值 |
| `AGENT_INTERNAL_TOKEN` | Java 调用 Agent API 的内部令牌 |
| `INTERNAL_DIAGNOSTICS_TOKEN` | 受保护诊断入口令牌 |

### Provider 模式

| 变量 | 说明 |
| --- | --- |
| `PROVIDER_MODE` | `DEMO_ONLY`、`REAL_ONLY` 或 `REAL_WITH_EXPLICIT_FALLBACK` |
| `DEMO_MODE` | 旧配置兼容：`true -> DEMO_ONLY`、`false -> REAL_ONLY`；与新值冲突时启动失败 |

### Provider 重试与降级

| 变量 | 说明 | 默认值 |
| --- | --- | --- |
| `PROVIDER_MAX_ATTEMPTS` | 最大尝试次数 | 3 |
| `PROVIDER_RETRY_BASE_DELAY_SECONDS` | 重试初始延迟 | — |
| `PROVIDER_RETRY_MAX_DELAY_SECONDS` | 单次最大重试延迟 | — |
| `PROVIDER_RETRY_MAX_ELAPSED_SECONDS` | 最大累计重试时间 | — |
| `PROVIDER_RETRY_JITTER_RATIO` | 重试抖动比例 | — |
| `PROVIDER_FALLBACK_CATEGORIES` | JSON 数组；可额外启用降级的 category | `[]` |

### 安全与 Cookie

| 变量 | 说明 |
| --- | --- |
| `REFRESH_COOKIE_SECURE` | 生产 HTTPS 必须为 `true` |
| `CITY_INTELLIGENCE_PLANNING_WAIT_TIMEOUT` | 规划前等待城市情报上限，默认 `PT2S` |

### 不可变镜像引用

Staging/production 必须为所有运行镜像提供完整 registry digest 引用：

| 变量 | 对应服务 |
| --- | --- |
| `POSTGRES_IMAGE` | 自定义 PostgreSQL/PostGIS/pgvector 镜像 |
| `REDIS_IMAGE` | Redis |
| `RABBITMQ_IMAGE` | RabbitMQ |
| `TRAVEL_SERVER_IMAGE` | Java API |
| `AGENT_SERVICE_IMAGE` | Worker、Agent API、knowledge-init 共用镜像 |
| `WEB_IMAGE` | Web/Nginx |
| `PROMETHEUS_IMAGE` | Prometheus |

每个值必须采用 `registry/repository@sha256:<64-hex-digest>`，不能只用 tag。生产/预生产从 registry 拉取制品，不在目标环境重新 build。

### 真实 Provider 变量

| 变量 | 说明 |
| --- | --- |
| `AMAP_WEB_SERVICE_KEY` | 服务端高德 Web Service Key |
| `QWEATHER_API_KEY` | 服务端 QWeather Key |
| `QWEATHER_API_HOST` | QWeather 控制台分配的专用 HTTPS Host |
| `VITE_AMAP_WEB_JS_KEY` | 浏览器高德 Web JS Key |
| `VITE_AMAP_SECURITY_CODE` | 浏览器高德安全密钥 |

## 启动命令

```powershell
docker compose -f compose.prod.yaml --env-file .env build
docker compose -f compose.prod.yaml --env-file .env up -d
docker compose -f compose.prod.yaml --env-file .env ps
```

`knowledge-init` 会在 Worker 启动前执行迁移和知识导入。服务健康后访问：

- Web：`http://127.0.0.1:8080`（端口可通过 `WEB_PORT` 调整）
- Java 健康检查：`http://127.0.0.1:8080/api/health`
- Prometheus：`http://127.0.0.1:9090`（端口可通过 `PROMETHEUS_PORT` 调整）

## Staging 验收运行手册

### 1. 候选与现场保护

开始前填写以下记录：

| 字段 | 必填证据 |
| --- | --- |
| Git 候选 | 完整 commit SHA、分支、审阅/批准记录；工作区必须无未提交产品变更 |
| 镜像 | 各服务的 registry digest；不能只记录 `latest` 或可变标签 |
| 编排 | `compose.prod.yaml` 内容摘要、Compose 版本、目标主机/集群标识 |
| 数据库 | 发布前 Flyway 版本、备份对象、恢复演练记录 |
| 配置 | 密钥库条目版本或引用、非敏感配置摘要 |
| 外部资源 | HTTPS 域名、证书到期日、AMap 应用、QWeather Host |

只读确认命令：

```powershell
git status --short --branch
git rev-parse HEAD
docker compose version
docker compose --env-file <private-staging-env> -f compose.prod.yaml config --quiet
docker compose --env-file <private-staging-env> -f compose.prod.yaml config --images
```

### 2. 无泄密配置预检

```powershell
python scripts/validate_staging_env.py --env-file <private-staging-env>
```

通过表示静态条件成立：`APP_ENV` 正确、镜像使用完整 digest、`PROVIDER_MODE=REAL_ONLY`、Secret 非示例值且互不复用、服务端与浏览器 Key 隔离等。不能证明凭据真实有效或第三方套餐可用。

### 3. 部署顺序与即时探测

1. 在变更窗口开始前完成数据库自定义格式备份，验证可读性和关键表计数。
2. 配置镜像 digest 并拉取，禁止 `--build`。
3. 等待所有服务健康，确认 `knowledge-init` 退出码为 0。
4. 通过最终 HTTPS 域名请求 Web 和 `/api/health`。
5. 记录开始时间、操作者、候选 SHA/digest、健康状态和证据位置。

### 4. 必跑验收矩阵

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| S-01 | HTTPS 与会话 | 证书链有效；登录、刷新、登出成功；Cookie 安全 |
| S-02 | CSP 与高德 Web JS | 底图正常；无 Key 时显示降级视图而非白屏 |
| S-03 | 真实规划成功 | `REAL_ONLY` 创建规划成功；Activity/Transit 为 AMAP |
| S-04 | QWeather 正向 | 当前天气、预报、历史天气各命中一个 |
| S-05 | QWeather 降级 | 失败可见，不伪装成 QWeather 成功 |
| S-06 | 配置失败 | 无效配置安全失败，不出现 Demo 成功 |
| S-07 | 城市刷新时序 | 超时/运行中/天气不可用均有正确状态 |
| S-08 | 核心用户旅程 | 新建、SSE、评估、天气、编辑、回滚、分享、导出全部完成 |
| S-09 | 幂等与故障恢复 | 重复命令不产生重复版本；重启后状态收敛 |
| S-10 | 日志与告警 | 日志不含敏感信息；告警可触发并恢复 |
| S-11 | 备份恢复 | 备份可恢复到隔离数据库，关键表计数一致 |
| S-12 | 应用回滚 | 回退上一组镜像后健康与核心读取通过 |
| S-13 | Soak | 连续至少 24 小时健康，无 P0/P1 |

### 5. 发布判定与停止条件

**发布条件：** S-01 至 S-13 全部通过、所有 Critical/Important 已关闭、候选 SHA 与镜像 digest 未变化、恢复与回滚真实执行。

**停止条件：** 凭据泄露、迁移不可恢复、`REAL_ONLY` 出现 Demo 结果、版本/所有权/幂等破坏、HTTPS 或 Cookie 安全失败、核心规划持续失败、队列无界增长。

## 备份与恢复

### 备份

```powershell
docker exec <postgres-container> pg_dump -U trip_pilot -d trip_pilot -Fc -f /tmp/backup.dump
docker cp <postgres-container>:/tmp/backup.dump output/backups/
```

备份前记录镜像标签、Git SHA、迁移版本和关键配置摘要。

### 恢复

1. 恢复到隔离数据库验证。
2. 确认 Flyway 版本匹配。
3. 逐表计数一致性验证。
4. API 读取验证。
5. 进入维护模式切换。

数据库迁移只向前；应用回滚不执行反向迁移。

## 回滚

- 应用镜像使用不可变 Git SHA 或发布标签。
- 回滚只切换上一组镜像和配置。
- 数据恢复只能使用已验证备份。
- 诊断重试必须幂等。

## 停止服务

```powershell
docker compose -f compose.prod.yaml --env-file .env down
```

需要删除本地演示数据时：

```powershell
docker compose -f compose.prod.yaml --env-file .env down -v
```
